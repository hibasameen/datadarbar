# Sindh Police annual reported-crime pipeline

Extracts and retains the annual crime figures for **2019–2025**: Sindh province
and its six police ranges, with **44 offence categories plus the published total**.
The selected table has **2,205 rows** (7 years × 7 geographies × 45 rows), including
2,156 offence counts and 49 reported totals. These are police-reported cases,
not estimates of all crimes committed, victims, convictions, or population rates.

The pipeline writes local CSV, JSON and Parquet files. It does not alter the public
Data Darbar site or the existing shared DuckDB database.

## Run

Run from the `datadarbar/` repository with Python 3.10+:

```sh
# Normalize already recovered, provenance-rich report JSON. No network.
python3 etl/sindh_police/pipeline.py build

# Re-extract retained original PDFs and saved indexed table responses, then build.
# Requires the Poppler pdftotext executable for the two original PDFs.
python3 etl/sindh_police/pipeline.py rebuild

# Use a different raw-source or output directory (global flags precede command).
python3 etl/sindh_police/pipeline.py --raw /path/to/sindh_police --out /path/to/output build

# Archive an explicit public report URL; PDFs must have a real PDF signature.
python3 etl/sindh_police/pipeline.py fetch 'https://www.sindhpolice.gov.pk/storage/statistic/1551180790_69721c548efb2.pdf'

# Retain a locally downloaded PDF, or import structured report JSON.
python3 etl/sindh_police/pipeline.py import-file /path/to/report.pdf --source-url 'https://example.org/original.pdf'
python3 etl/sindh_police/pipeline.py import-file /path/to/recovered_report.json

python3 -m unittest discover -s etl/sindh_police -p 'test_*.py' -v
```

CSV and JSON use only the Python standard library. Parquet uses PyArrow or a
native DuckDB fallback; the existing Anaconda Python environment provides DuckDB.
`requirements.txt` lists the optional Parquet packages. No private credentials are
required. Downloading a PDF archives it; arbitrary new PDF layouts are not silently
parsed by the historical fixed-layout extractors.

`rebuild` runs three versioned adapters: `extract_archived_pdfs.py`,
`extract_2023_recovery.py`, and `extract_2024_2025_recovery.py`. Each accepts
`--raw-dir` and `--out-dir`. It writes reconstructed report extracts beneath the
output directory, keeping downloaded evidence unchanged. The historical PDF parser
uses the reviewed, versioned `category_schema.json` and checks the actual printed
labels, table widths, annual dates, category totals, and range totals.

## Coverage and source selection

| Observation years selected | Official report edition | Evidence |
|---|---|---|
| 2019 | Annual 2020, prior-year comparison | Original official PDF from public web archive, pages 1–2. |
| 2020–2021 | Annual 2021, prior/current-year comparisons | Original official PDF from public web archive, detailed tables on pages 5–7. |
| 2022–2023 | December 2023 year-end comparisons | Retained search-index text of the official PDF, pages 1, 3 and 4. |
| 2024–2025 | December 2025 year-end comparisons | Retained search-index text of the official PDF, pages 1, 3 and 4. |

The live Sindh Police PDF host returned HTTP 403 during extraction. The 2019–2021
counts were recovered from archived original PDFs. The 2022–2025 counts were recovered
from search-indexed official tables: these are not claimed to be original PDF bytes,
and their indexed content may reflect an earlier source snapshot. Exact original
URLs, archive URLs, document/evidence paths and hashes are retained.

Annual selection requires explicit dates from 1 January through 31 December and
`is_full_year=true`. Monthly or partial-year values are never annualised. A candidate
report edition must contain the same 45 category keys for all seven geographies;
province and range extracts with the same source URL/reporting year can form one
edition. A partial recovered 2024 edition remains in observations but cannot replace
cells in the selected table.

Among complete eligible editions, the largest explicit `source_priority` wins;
the initial sources use their report year as priority. This chooses the newest
complete recovered comparison, preserving revised source values. Equal-priority
disagreements are withheld from the selected table and reported for review. All
alternatives retain their own count and provenance. Exact duplicate JSON payloads
are read once even after import; alternative snapshot paths remain in source metadata.

## Data dictionary

`catalog.json` gives exact field names and types for every output. Dates are ISO
strings, counts are nullable signed 64-bit integers, and flags are booleans.

| Columns | Meaning |
|---|---|
| `year`, `period_start`, `period_end`, `is_full_year` | Observation period, distinct from report edition. |
| `reporting_year`, `comparison_column` | Report's own year and the original current/prior-year column. |
| `geography_level`, `geography_name`, `geography_key` | Published geography and stable lookup key. The six ranges are Karachi, Hyderabad, Mirpurkhas, Shaheed Benazirabad, Sukkur and Larkana. |
| `crime_category_raw`, `category_group`, `crime_category_key` | Original label/group and reviewed spelling-normalised key. Source misspellings remain visible. |
| `row_type` | `detail`, `subtotal`, or `total`. Selected historical tables have 44 detail categories and one total. |
| `metric`, `cases_reported`, `value_raw` | Metric is `cases_reported`; nullable parsed integer plus original cell text. |
| `report_id`, `observation_id` | Report snapshot identifier and deterministic observation hash. |
| `source_url`, `source_type`, `extraction_method` | Original official URL, evidence type, and recovery method. |
| `source_snapshot_path`, `source_snapshot_sha256` | Recovered report JSON snapshot used by the build and its SHA-256. |
| `source_document_path`, `source_document_sha256`, `source_archive_url` | Original PDF provenance where archived PDF bytes were recovered. |
| `source_page`, `source_row`, `source_column` | Source location; PDF page numbers start at 1. |
| `evidence_path`, `evidence_sha256` | Saved indexed-response evidence for observations that name an evidence file. |
| `validation_status`, `selection_eligible`, `selection_status` | Validation result, complete-edition eligibility and why the row was selected or excluded. |
| `observation_metadata_json` | Full recovered observation metadata, including original difference cells and recovery blocks where supplied. |
| Source table `source_metadata_json` | Complete report metadata, source notes, evidence hashes and published difference-column anomalies. |

## Checks and limitations

The build checks explicit dates, nonnegative integer counts, raw/parsed agreement,
source-fact uniqueness, declared document/evidence hashes, report completeness,
category totals, and six-range sums against the province. It reports missing years
and missing categories relative to the recovered category union. Nulls remain null;
no missing cell is imputed as zero. Arithmetic mismatches stay visible and are never
silently corrected. A changed source layout makes its extractor fail explicitly.

The 2021 report contains 39 inconsistent printed difference cells in its detailed
tables. The counts are retained, the printed differences are recorded separately,
and all extracted count totals reconcile. Inconsistent overview summaries from that
report are excluded. The original 2024 indexed province page contains a November
headline despite December and full-year column headings; that report is retained as
an alternative with the discrepancy documented and is not selected.

These geographies are **police ranges, not civil districts**. Province and range
rows overlap. Category totals overlap their details. Do not sum multiple geography
levels, source editions, or detail/subtotal/total rows. Counts are not crime rates;
no population denominator or geographic boundary crosswalk has been attached.

## SQL examples

Run these with DuckDB from the output directory, or replace filenames with full paths.

```sql
-- One province-wide published total per year.
SELECT year, cases_reported, reporting_year, source_url
FROM 'sindh_crime_annual.parquet'
WHERE geography_key = 'province:sindh' AND row_type = 'total'
ORDER BY year;

-- Murder cases by police range, one selected source edition per year.
SELECT year, geography_name, cases_reported
FROM 'sindh_crime_annual.parquet'
WHERE geography_level = 'range' AND crime_category_key = 'murder'
ORDER BY year, geography_key;

-- Inspect source alternatives and why they were excluded.
SELECT year, reporting_year, crime_category_raw, cases_reported, selection_status, source_url
FROM 'sindh_crime_observations.parquet'
WHERE geography_key = 'province:sindh'
  AND crime_category_key = 'assault_on_police'
ORDER BY year, reporting_year;
```
